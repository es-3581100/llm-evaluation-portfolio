About / trajectory
01 / 05

From evaluation into systems.

I’m an experimental AI systems builder with a nontraditional path into software and a habit of turning abstract problems into inspectable working structures.

My earlier portfolio centered on LLM evaluation, retrieval quality, adversarial testing, persistent-agent reliability, and safe tool use. That work still matters; it taught me to separate evidence from confidence and to keep claims bounded by what a system actually demonstrated.

The work has since widened. I now spend much of my time designing agent control planes, AI-native applications, model-aware developer systems, provenance infrastructure, technical visualizations, and cross-language experiments.

About / evaluation approach
02 / 05

Evidence before confidence.

Evaluation is no longer the whole portfolio. It is the verification layer underneath how I build.

I separate similarity, factual support, policy permission, live-state availability, and safe answerability instead of treating them as one fuzzy idea of “correctness.” AI-generated output is proposal material to verify, not independent evidence that a system works.

That approach grew through retrieval evaluation, persistent-agent reliability work, adversarial testing, and authority-boundary analysis. The same instinct now shows up in build ledgers, runtime readback, deterministic fixtures, provenance records, and narrow execution gates.

About / working principles
04 / 05

Make the hidden parts inspectable.

01

Make invisible systems visible.

Expose state, relationships, provenance, and uncertainty instead of hiding them behind a polished interface.

02

Separate reasoning from authority.

A model may propose, explain, or investigate without silently inheriting permission to execute.

03

Preserve evidence as you build.

Tests, hashes, receipts, and failure records are part of the system, not cleanup after the interesting work.

04

Cross boundaries deliberately.

Use Kotlin, Go, Python, browser systems, symbolic math, native runtimes, or ML when the problem benefits from the boundary crossing.

About / current direction
05 / 05

Architecture still to be discovered.

I’m interested in applied AI systems, agent engineering, developer tooling, model-integrated applications, technical interfaces, and unusual cross-domain problems where the architecture still needs to be discovered.

I use AI heavily in the build process, but model output is not treated as independent evidence. The engineering goal is to make increasingly capable workflows more inspectable, reproducible, and useful—not merely more autonomous.
